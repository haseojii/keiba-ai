# PR Summary: #3

- PR: https://github.com/haseojii/keiba-ai/pull/3
- Title: features層の最小スケルトン導入と学習フロー分離
- Base/Head: `master` <- `codex/features-skeleton`

## What Changed
- `src/keiba_ai/features/` を新規追加した。
  - `__init__.py`
  - `build_features.py`
- `scripts/train_baseline.py` を更新し、学習フローを
  `load_data -> build_features -> train_baseline_model` にした。
- `README.md` にfeatures層の目的と導入理由を短く追加した。
- 実験ログを追加した。
  - `logs/experiments/2026-03-08_features_layer_v1.md`

## Why Changed
- 次段階で特徴量追加を始める前に、責務分離を明確にするため。
- 既存のサンプルデータ動作を維持しつつ、拡張しやすい構造にするため。

## Important Design Decisions
- features層は最小実装に留め、重い抽象化は導入しない。
- target分離と特徴量テーブル構築の責務を `features/` に寄せる。
- モデル学習ロジック (`models/`) はそのまま維持する。

## Lessons Learned
- 小さな層追加でも、将来の変更点を集約する場所ができる。
- フローを明示するだけで、初学者にとってコードの見通しが良くなる。

## Follow-up note
Current target handling is slightly duplicated across `features` and `models`.
This is acceptable for the current stage, but later we should consider making `features` responsible for producing training inputs and `models` responsible only for training.

## Likely Next Steps
1. `features/` に小さな変換を1つ追加し、ログで比較する。
2. 変換の有無でベースライン結果を記録していく。
3. `evaluation/` の最小スケルトンを追加する（複雑化はしない）。
